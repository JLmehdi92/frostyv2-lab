### 1.2 Méthode

- **Analyse statique** avec **REA CLI 6.4.0** :
  - `inspect-android-package` (fournisseur JADX headless 0.7.1) → preuve **REA-PKG** : manifeste complet, permissions, nombre de classes et de ressources.
  - `decode-android-resources` (fournisseur Apktool 3.0.3) → preuve **REA-RES** : manifeste, métadonnées, chaînes.
- **Décompilation complète** : JADX 1.5.6 (`~/twitch-re/jadx-base`) et Apktool 3.0.3 (`~/twitch-re/apktool-base`). Elle sert à vérifier les noms cités par REA et ceux hors de sa projection.
- **Bundle React Native** (`assets/index.android.bundle`, Hermes bytecode v98) : table de chaînes décodée par un parseur d'en-tête maison. Seuls des identifiants sont cités (ex. `VideoStatsOverlay`), jamais du texte d'interface.
- **Flags Eppo** : `assets/eppo.json` (instantané du 2026-10-06). Un flag présent ne prouve pas que la fonctionnalité est active.
- **Analyse dynamique sur émulateur** : **à compléter**. La colonne de preuve prévoit un préfixe `dyn:`, laissé vide pour l'instant. Tous les comportements décrits ici sont **déduits statiquement** et restent à confirmer à l'exécution.
- **Contrôles croisés effectués** : un script a vérifié chaque nom cité (`str:`, `cls:`, `gql:`, `topic:`, `flag:`, `rn:`, `res:`) dans `apktool-base`, `jadx-base`, `eppo.json`, le bundle RN et `notes/protocols.md`. Exemples contrôlés à la main :
  - `setLiveCatchUpSpeedUpEnabled(true)` dans `TwitchPlayerConfigKt` et dans une classe obfusquée.
  - Défaut `true` de `setLiveLowLatencyEnabled` et `false` de `setRebufferToLive` dans le pont `NativeVideoOverlayPlugin`.
  - `setInitialBufferDuration(100L)` / `(300L)`.
  - Présence de `app_settings_background_audio` dans la projection REA-RES.

**Implications pour ONSET** (rappel, non normatif) :

1. Passer à `ivs-player:1.57.0` et activer `setLiveCatchUpSpeedUpEnabled(true)`.
2. Faire de `rebufferToLive` une option plutôt qu'un défaut.
3. Fixer un buffer initial d'environ 100 ms.
4. Précharger le jeton et le manifeste dès que l'utilisateur montre son intention d'ouvrir un stream.
5. Nettoyer les paramètres usher.
6. Afficher la latence par défaut pendant les mesures.

**Points d'incertitude :**

- Les comportements sont déduits statiquement. Les preuves `dyn:` restent à produire sur émulateur.
- Plusieurs features dépendent de flags Eppo à déploiement ciblé (Ultralight, portails, Stories `Android-Briefs`=false, Skyline). Elles ne sont pas forcément visibles pour un compte donné.
- Le rattachement de quelques opérations à leur feature est probable mais non certain : `VideoCommentsQuery` pour le chat replay, `OneTapFeedQuery` pour les Combos, le topic AutoMod côté émetteur.
- Les opérations marquées « (portail) » n'existent que dans la build Twilight embarquée et ne sont utilisées que si le portail correspondant est actif.
