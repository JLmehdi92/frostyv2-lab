## Mobile-only behaviour and its PC replacement

| Android | PC |
|---|---|

| Play Store in-app review | None (no store) |
| Audio focus / headphone unplug | Pause on device removal and communications ducking (decision D8) |

| Refresh-rate request | Vertical sync |
| Per-app language (Android 13) | ONSET language setting |
| Picture-in-picture and floating overlay window | Always-on-top mini-player window; in-app mini player kept (decision D5) |
| WorkManager background go-live check | Tray-resident app running the 90 s poller (decision D6) |
| Local notifications + permission prompt + notification settings link | WinRT toasts (decision D7); Windows notification settings via `ms-settings:notifications` |
| IVS Android player | Rust LL-HLS fetcher (Twitch prefetch) + libmpv, same event contract (decisions D1, D2) |
| media_kit | libmpv directly |
| webview_flutter + TwitchCookies | wry (WebView2), cookie read via WebView2 cookie manager, loaded only when needed |
| Metered-network bridge | WinRT `NetworkInformation` connection cost |
| Launch info / splash tile | Launch intro storyboard drawn in-app; single instance + protocol links (`twitch://`, `ttv://`) |
| flutter_secure_storage | OS keyring (Credential Manager) |
| SharedPreferences | JSON settings file with identical keys and defaults |
| Firebase Crashlytics/Analytics/Performance (optional) | Off by default, same consent rules; optional crash reporting backend behind the `Telemetry` trait |
| image_picker | Native file dialog (rfd) |
| wakelock | Power request (decision D9) |

| Clip download to gallery | "Save as…" dialog |
| APK installer | Velopack installer + updater with SHA-256 (decision D4) |
| Google Cast SDK | rust_cast + mdns-sd (decision D10) |
| AndroidManifest permissions/intents | Windows app manifest, protocol registration, autostart entry |
| assets/ (fonts, icons, celebrations) and lib/l10n ARB files | Reused as-is: Inter fonts, PNG/SVG art, ARB strings compiled into the Rust i18n |

### 01-home.md


1. **Hero ignores "Hide viewer count".** Android: `LargeStreamCard`'s top-left pill (`OverlayPill` + `RollingViewers`) shows the viewer count even when `hideViewerCount` is on (every other count is hidden). PC: hide that pill (and its semantics label) when the setting is on, like `ViewerPill`.
2. **Categories store lifetime.** Android: `BrowsePage`'s `CategoriesStore` is `late final` — the top-categories request is only sent when the Categories tab is first built, and the store is never disposed (no dispose, its future can complete after the page is gone). PC: create it with the Browse page (or prefetch at idle) and drop/cancel it when the page is destroyed.
3. **Live feed staleness uses the wall clock.** Android: `LiveFeedStore.stale` and `refresh()` use `DateTime.now()`, so a wall-clock change (DST/manual clock) can force or suppress the 5-minute refresh. PC: use a monotonic clock (`Instant`) for staleness and TTLs.
4. **topTags can show 9 chips.** Android: when the selected tag is outside the 8 most used, the chip row shows selected + 8 = 9 tags (selected inside the top 8 → selected + 7 = 8). **PC decision: at most 8 tag chips in total — the selected tag (if any) first, then up to 7 others in rank order, never repeating the selected one** (no selection → the 8 most used). The ported test "tags rank by use, filter the list, and stay listed when picked" is adapted to this cap.
5. **Stale ListStore pages leave nothing to clean.** Not a visible bug today (the newer request owns the loading flag), but a stale answer that arrives after the newer one has finished never re-runs hype trains / sort paging; PC must keep the same rule: only the current generation touches loading state and follow-ups.
6. **Related lives strip misaligned and cards touching.** Android: the strip's padding is `gutter + window.left − 8` / `gutter + window.right − 8`, but tile-mode `StreamCard`s have zero horizontal padding, so nothing absorbs the −8: the first card starts 8 dp left of the "Related lives" title (x = 8 on a phone, 20 on a tablet, vs title at 16 / 28) and card edges touch. PC: remove the −8 (pad `gutter + inset` both sides) and put a 12 px gap between cards.
7. **Stale search results during the debounce.** Android: for 300 ms after each keystroke the previous query's channels/categories stay shown (skeletons only for the first query), while "Go to channel “<new text>”" and the featured card are computed from the new text against the old list. PC: on every non-empty text change clear the channel/category results (and related lives) immediately and show skeletons until the debounced search runs.
8. **Spaces-only / untrimmed queries.** Android: `onSearchTextChanged` and `handleQuery` test `query.isEmpty`, so "   " calls `/search/channels` and `/search/categories` with `query=%20%20%20` and is saved to history; "Go to channel" passes the raw text to `getUser(userLogin:)`, so " xqc" is "not found". PC: trim the query before deciding emptiness, before searching, before saving to history and before "Go to channel" (the videos store, suggestions and `featuredChannel` already trim).
9. **Related lives ignore blocked and hidden channels.** Android: `_loadRelatedLives` only removes channels already shown live; blocked users and `hiddenChannelIds` can appear (every other list removes blocked users; Browse lists remove hidden channels). PC: also remove `authStore.user.blockedUsers` ids and `settings.hiddenChannelIds` before taking 6.
10. **Followed-videos badge leaks across accounts.** Android: `NewFollowedVideos.count` and `_checkedAt` are process-wide statics never reset on account change, and `followedVideosSeenAt` is one global setting: switching account A → B within 30 min shows A's count on B's tile, and later B's videos are counted against A's seen time. PC: key the seen time, the count and the recheck clock by user id, and reset the in-memory state on account change.

**Monogram hash (not a defect — reproduce exactly).** `_Monogram` picks `_washes[seed.hashCode.abs() % 6]` with `seed = category.id`. The Dart VM (`runtime/vm/hash.h` + `StringHasher` in `runtime/vm/object.h`, SDK 3.10) hashes a string's **UTF-16 code units** with 32-bit unsigned wrapping arithmetic:
```
h: u32 = 0
for each UTF-16 code unit c:      // CombineHashes
    h = h + c
    h = h + (h << 10)
    h = h ^ (h >> 6)              // logical shift
// FinalizeHash(h, kHashBits = 30)
h = h + (h << 3)
h = h ^ (h >> 11)
h = h + (h << 15)
h = h & ((1 << 30) - 1)
if h == 0 { h = 1 }
```
The result is always in `1 ..= 2^30 − 1`, so `.abs()` is the identity; index = `h % 6`. Category ids are ASCII digits (one-byte strings in the VM; same code units). Vectors verified on the Dart 3.10.3 VM (`dart run`, 2026-11-18): `"509658"` → 940227327 → wash 3; `"21779"` → 935305111 → wash 1.

Real bugs found in the Android code. The PC port must not copy them; each entry gives what Android does and the PC fix.

### 07-social.md


Exact Android behaviour today, and what the PC port does instead (each is a deliberate, documented fix — nothing else changes silently):

1. **Stale Activity follow cache** (`activity_screen.dart` `_followStates`, lines 256–265, and `_EntryFollow.onChanged`, 832–834). ### 08-settings.md

1. **Settings decode can crash startup.** `SettingsStore.fromJson` hard-casts every non-enum field (`as bool?`, `as num?`, `as String?`, list elements `as String`, `notInterestedChannels` values `as String`, `secondaryTabs` items `as Map<String, dynamic>`, `landscapeChatModes as List?`) and `jsonDecode` throws on a corrupt file; main.dart has no try/catch, so one wrong-typed value or a truncated `settings` string makes the app fail at launch, forever. PC fix: tolerant per-field decode — each field falls back to its JSON default on a type error; an unparsable file loads all defaults and is kept as `settings.json.bak`.
2. **`landscapeCutout` has no unknown-value fallback.** Its `@JsonKey` has a `defaultValue` but no `unknownEnumValue`, so an unknown string (e.g. a value written by a future version) throws `ArgumentError` in `$enumDecodeNullable` → startup crash (same path as 1). PC fix: unknown → `none`.
3. **Logout can stop half-way.** In `_endSession`, after clearing the web session and running the listeners, one try/catch wraps the rest: if reading `user_token` throws (keystore) or `_useAppToken()` throws a non-`ApiException`, the revoke, deletion of `user_token`/`user_token_client_id`/`user_id`, nulling the token, `user.dispose()`, `_isLoggedIn = false` and the telemetry key are skipped — the UI still shows the account. PC fix: run every logout step independently (each in its own guarded block), always ending in the logged-out state.
4. **UserStore keeps the previous account's blocked list.** `init()` never clears `_blockedUsers`; the blocked-list fetch is fire-and-forget without `catchError`; an account switch calls `init(details:)` without `dispose()`. Account B therefore shows A's blocked users and count until B's fetch succeeds, or indefinitely if it fails (and the failure is an unhandled async error). `refreshBlockedUsers` throws when logged out (`_details!`). PC fix: clear the list on every init/switch, handle fetch errors (keep empty + retry on refresh), no-op refresh when logged out.
5. **The reconnect loop logs out silently.** When the loop finds the stored token invalid, or gives up after 5 attempts, `_logoutFromReconnect` runs `_endSession()` only; `TokenNotice.sessionEnded` is raised only by `init`'s invalid-token path. The viewer is logged out with no explanation (exhaustion only writes `Telemetry.log`). PC fix: raise the "session ended, log in again" notice on the invalid-token path of the loop too (and on exhaustion, say Twitch could not be reached).
6. **TwitchTvSession: a superseded grant stays on disk.** `_store` writes `twitch_tv_session` before re-checking the generation; if a detach/forget/attach happened during the write it returns `cancelled` but leaves the new session stored (it will be adopted, or deleted as another account's, at the next attach). PC fix: re-check after the write and delete (and revoke) the written session when superseded, or write under the same lock as the generation bump.
7. **AccentThrottle late write.** The trailing 100 ms timer always re-applies the latest colour and the picker never flushes/cancels on close, so a write can land up to 100 ms after the picker closed. Harmless (it is the last colour) but racy with a Reset in that window. PC fix: flush on close, keep "last colour picked is saved".
8. **`loginFromClipboard` is untrimmed and silent.** It passes the raw clipboard text (only null filtered) to `login(acceptAnyApp: true)` without awaiting it: whitespace around a token or an empty clipboard fails with no feedback. PC fix: trim, ignore empty, await and show success/failure.
9. **Gift / whisper Undo throws after the page closes.** The result snackbar goes to the root messenger and survives popping Settings › Account; its Undo calls `_apply` on the disposed State (`ScaffoldMessenger.maybeOf(context)` / `setState` throw), unawaited, so the revert is never sent and the error is unhandled. PC fix: run the undo through a service/store that outlives the page (re-send the previous value with its own result toast), or remove the action when the page closes.
10. **Connect sheet says "Couldn't reach Twitch" for a cancel.** `twitchTvConnectResult` has no `cancelled`/`failed` branches; a `cancelled` outcome reaching a mounted sheet (account switched or generation superseded during `_store`) shows the network-error `other` text. PC fix: close the sheet silently on cancel (or a dedicated "cancelled, try again" text); keep "Couldn't reach Twitch" for real failures.
11. **Unknown hidden-content-label ids are stuck.** They count in the row but have no checkbox in the sheet and survive every toggle; only a General reset removes them. PC fix: list unknown stored ids as extra checkable rows (named by CamelCase split), or drop them on load.
12. **Chat bubbles: unknown/duplicate names.** Unknown or duplicated stored names inflate the row's count until the first toggle, which silently rebuilds the list from the enum and drops them. PC fix: normalise on load (known names, canonical order, deduplicated) so the count is always right.
13. **Remote settings loaders: empty = unavailable, and no error guard.** The Twitch notification settings show "unavailable" for an empty list too; gift, whisper and notification groups' `_reload` have no try/catch, so a throwing loader leaves an endless spinner. PC fix: loaders never throw (map every error to `None`), distinguish "empty" (show nothing/a neutral note) from "unavailable", and always clear the spinner.
