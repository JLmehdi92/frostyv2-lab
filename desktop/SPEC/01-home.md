# 01 — Home: shell, Following, Live feed, Browse, categories, tags, search, continue watching, followed videos

> Cross-spec decisions in [00-index.md](00-index.md) (section "Decisions") override any conflicting PC suggestion in this file.

Source of truth: `lib/screens/home/**` (17,132 lines of Dart, generated `.g.dart` excluded) and its tests `test/screens/home/**`. Every number below is copied from the code. Token names refer to `lib/theme.dart` (`OnsetTokens`, `OnsetSpacing`, `OnsetType`, `OnsetColors`) and `lib/widgets/motion/motion.dart` (`OnsetMotion`); their values are restated inline where they matter.

## Purpose

This area is everything the viewer sees between launching ONSET and opening a channel, a VOD or a clip:

- **The navigation shell** (`OnsetShell`, `Home`, `HomeStore`, `ShellPages`, `ShellTabs`, `ShellGlyph`): four sections — **Home**, **Browse**, **Activity**, **Profile** — with a glass header and a floating bottom bar on phones, and a top bar with a pill navigation on tablets. Home has three top tabs: **Following** (logged in only), **Live**, **Clips** (the clips feed itself belongs to the clips area and is only hosted here). Browse has two tabs: **Categories** and **Live channels**. Activity has **Notifications** and (logged in) **Whispers** (Activity's content belongs to another area; its header/tab wiring is here). Profile is the account/settings page (other area) with a gear button in the header.
- **Following** (`StreamsList(listType: followed)`): "Continue watching" shelf, a hero live card, "Live now N" with a sort menu, pinned channels, other live channels, the followed-videos entry tile (with a "new" badge), the followed categories, the collapsible offline channels. Pull to refresh, auto-refresh after 5 minutes.
- **Live feed** (`LiveFeed`, `LiveFeedStore`, `LivePreviewController`): a TikTok-style vertical feed of the top live channels, one per page, each with a muted low-resolution **libmpv preview** (media_kit), category chips, "Not interested", share, follow, content-warning gate, data-saver / Wi-Fi-only awareness, and an "Up next" column on tablets.
- **Browse**: top categories grid (3+ columns, infinite paging) and top live channels list; on a landscape tablet ≥ 1000 dp wide, a 448 dp category rail beside the chosen category's page (master/detail).
- **Category page** (`CategoryStreams` / `CategoryView`): hero header with box art wash, "Follow on Twitch", Live / Videos / Clips sections, sort menu for live streams.
- **Tag page** (`TagStreams`): live streams with one tag, sortable, glass header.
- **Search** (`SearchScreen`, `Search`, `SearchStore`, `SearchVideosStore`): field with history (8, persisted), live suggestions (history + Twitch GQL), results under Top / Channels / Categories / Videos, exact-match featured channel, "Go to channel", tag link, related lives; kept between opens as a `SearchSession`.
- **Continue watching** (`ContinueWatchingStore`, shelf/column/screen): merges this device's saved VOD positions with Twitch's own resume shelf.
- **Followed videos** (`FollowedVideosStore`, `FollowedVideosScreen`, `NewFollowedVideos`): newest VODs of followed channels in Today / Yesterday / This week / Older, with a new-videos badge.
- **One-shot prompts on Home**: the one-time language question (`language_prompt.dart`), the release notes after an update, the feedback prompt (`feedback_prompt.dart`, 12th open then every 30 opens), the token notice snackbar, whisper notices, and the in-app update offer ordering.

Low-latency mission hooks in this area: a finger landing on any live card/preview/Watch button calls `PlaybackPreloader.instance.preload(login, engine, authToken)` so the playback token is fetched while the channel page opens; the Live feed's preview shares `PlaybackTokenCache.shared` so the channel opens with a warm token; the preview decoder is released (≤ 100 ms wait) before the channel's own player starts so they never share the device.

## Behaviour and state

### Shell navigation (HomeStore)
- Start place from setting `startTab` ("Open the app on"): Following → Home/Following (Live when logged out); Live → Home/Live; Clips → Home/Clips; Browse → Browse (Home tab Following, or Live logged out). Legacy saved values `'top'` → live, `'search'` → browse.
- Tapping the current section / tab scrolls its list to the top (300 ms, standard curve): Home → Following list or Live `PageController` to page 0 (Clips: nothing); Browse → current tab's list; Activity/Profile → nothing. A change gives a selection haptic.
- Leaving Home while on Clips switches Home's tab back to the rest tab (start tab, or the first tab if the start tab is Clips) so returning never restarts the clips.
- Android back (`PopScope`): not on the start section → go to the start section (stopping clips); on Home but not on the rest tab → rest tab; else leave the app (`canLeave` lets the pop through).
- Logging in/out: Following and Whispers appear/disappear; a vanished tab yields (Home → rest tab, Activity → Notifications); logging in while off Home resets Home's tab; the visible section never changes.
- `Home.openPlace(browse|following|activity)` and `Home.openSearch(term)` are global entry points (links, notifications, chips).

### Page lifecycle
- Pages are built on first show and kept (`ShellPages`), offstage with tickers off when hidden; the Clips page is not kept (exists only while on screen). Home caches page widgets by their inputs so hidden pages are not rebuilt.
- The Live feed is `active` only when its page is current, Home is the section, and nothing covers the shell; Clips additionally never play under the launch intro.
- "Covered" = any `PageRoute` above Home's route in the navigator (dialogs/sheets alone don't count; a page opened from a sheet does). Covered → mini player released from the shell chrome; uncovered → the mini player is told the chrome insets (header top / bar bottom) after each frame.

### Greeting sequence when Home comes in front (once per launch)
1. Free orientation (`setPreferredOrientations([])`) — once.
2. Language question if `languagePromptVersion < 1` (after the launch tile lands, only if not covered).
3. Release notes if an entry exists for the new version (`last_shown_version` in SharedPreferences; first launch only records the version; unreadable notes decide nothing after an update).
4. Feedback prompt: count this open; ask if `appOpens >= feedbackPromptAtOpen` (first at 12) and not done; Later → +30 opens; Never / Send → done (Send opens `<repo>/issues/new/choose`, external browser if `launchUrlExternal`).
The in-app update offer waits until the language question is settled. A token notice (account token made for another app) shows once as a 6 s snackbar after the intro lands. Whisper notices show over any screen unless that conversation is open; one at a time; closed when the account changes.

### Following list (ListStore followed)
- Live streams: Helix `/streams/followed` paged by cursor (prefetch when 10 from the end); pinned channels fetched separately by id (`/streams?user_id=…`) and shown first; blocked users removed; order from setting `followedSort` (viewers keeps Helix's order; others load up to 5 extra pages then sort stably: recent, name, category, recommended = watch streak then viewers).
- Extras (never block the list, 30 min backoff after a refusal, need the twitch.tv web token): followed categories (GQL `FollowedGamesQuery`), watch streaks (GQL `BatchGetWatchStreaksQuery`), hype-train statuses for card pills (GQL `HypeTrainStatuses`, setting `showHypeTrain`).
- Offline channels loaded only when expanded (Helix `/channels/followed`, 20 per page, prefetch 5 from the end), freed on collapse; exclude live, pinned and blocked.
- Filters: language chip (local filter on Following; refetch elsewhere), up to 8 top tags (local), Clear.
- Refresh: pull (light haptic) or on resume / becoming visible when ≥ 5 min old; errors as a snackbar if streams were shown, else a full status view with "Try again".

### Live feed
- List = top streams (or a chosen category from the chips), minus "Not interested" channels (persisted map `notInterestedChannels`, Undo snackbar). Chips = up to 4 most frequent categories of the first page, recomputed only when the list starts over; the chosen chip is kept.
- One preview at a time: starts 350 ms after the page settles; stops at once when inactive (another tab/section, covered, background, mini player visible, launch intro, enlarged picture dialog, channel opening); never two decoders; muted unless setting `mutePreviews` is false; per-preview mute toggle.
- Autoplay = `streamPreviews` on AND `vodAutoplay` (always / Wi-Fi only (unmetered) / never) AND not (data saver && metered≠false) AND `showThumbnails`; otherwise a Play button starts it by hand. Network metering is re-asked on each resume and followed live (leaving Wi-Fi stops a Wi-Fi-only preview).
- Content warnings (setting `warnMatureContent`): each channel's labels are read (Helix `/channels`, once per channel, TTL 10 min, all again on refresh). A labelled or unknown-labels channel never previews unasked: it shows "Content warning · Play preview" → the channel's `ContentWarningCover` → "Start watching" (accept for this session → plays) or "Go back".
- Tap / Watch with chat → release the preview (≤ 100 ms) → open the channel; previews stay off until the channel page has fully closed. Long press on the picture → enlarge (or actions if thumbnails off); long press on the lines → stream actions.
- Index follows the page; next page fetched 3 from the end; a page after the last channel shows loading (`liveFeedLoadingMore`, "Loading more live channels…") / error + Try again / `liveFeedEnd` ("That’s every live channel here for now") + `liveFeedBackToFirst` ("Back to the top"). Pull to refresh on the first page. Coming back after ≥ 5 min (or resuming while active) refreshes keeping the channel on screen.

### Search
- Typing: suggestions immediately from history, Twitch suggestions merged after 150 ms; results after a 300 ms debounce. Skeletons appear at once **only when no results exist yet** (first query of the session, or after the field was emptied): `onSearchTextChanged` sets `isSearching = true` but does not clear `channelFuture` / `categoryFuture`, and the result widgets show skeletons only when their future is null. So for 300 ms after each keystroke the previous query's results stay on screen while "Go to channel “…”" and the featured card are recomputed against the new text (Known defect). Empty checks use `query.isEmpty`, not `trim()`: a spaces-only query is searched and saved to history (Known defect); submit/history/suggestion runs immediately. Each search goes to the top of the 8-entry history (SharedPreferences `search_history`).
- Channels: Helix search (8), live first; exact login/name match featured; blocked removed; "Go to channel “q”" resolves a login directly. Categories: Helix search (8), exact name first. Related lives: up to 6 live streams of the first category result not already listed. Videos: GQL search, 25 per page up to 10 pages / 250 videos.
- A channel suggestion opens the channel profile directly. A single-word query offers `searchLiveWithTag` ("Live channels tagged q").
- The session (query, results, history, tab, scroll offset, videos store) survives closing and reopening search; a kept search reopens without the keyboard.

### Continue watching / followed videos
- Shelf = merge of local positions and Twitch's resume shelf (later save wins), newest first, max 20, finished or within 30 s of the end removed, deleted videos dropped until next load; updates live when a VOD closes.
- Followed videos: up to 100 followed channels → 5 newest videos each (GQL) → top 100 newest; badge = videos newer than `followedVideosSeenAt`, re-checked at most every 30 min; opening the list marks seen.

## Animations and motion

Motion tokens (`OnsetMotion`): `springStandard` = critically damped, 350 ms (`SpringDescription.withDurationAndBounce(duration: 350 ms)`); `springMomentum` = 400 ms, bounce 0.2; `emphasizedDecelerate` = `Cubic(0.05, 0.7, 0.1, 1)`; `emphasizedAccelerate` = `Cubic(0.3, 0, 0.8, 0.15)`; `standard` = `Cubic(0.2, 0, 0, 1)`; `overshoot` = `Cubic(0.3, 1.5, 0.5, 1)`; `pressScale = 0.97`; `pressDuration = 100 ms`; `enter = 350 ms`; `exit = 250 ms`; `reducedFade = 150 ms`; `staggerStep = 40 ms`; `launchStaggerStep = 60 ms`; `staggerCap = 8`. Reduce motion = Android "Remove animations" (`MediaQuery.disableAnimations`) or iOS Reduce Motion (`accessibilityFeatures.reduceMotion`); `motionDuration(context, d)` returns 150 ms under reduce motion.

| Element | Mechanism | Values | Reduce motion |
|---|---|---|---|
| Section / Home tab / Browse tab change (`ShellPages`) | unbounded controller, `SpringSimulation(springStandard, 0→1, v0 0, tolerance velocity 0.01)` | new page opacity t, offset lateral `24 × direction × (1−t)` px horizontally (Home tabs, Browse tabs; direction = sign of index change) or rise `8 × (1−t)` px (sections); old page opacity `1−t`, no travel; `onSettled` when done | `animateTo(1, 150 ms)` linear cross-fade, no travel |
| Tab underline (`ShellTabs`) | `AnimatedPositioned` left/width | 300 ms, `standard`; 2.5 dp tall, radius 2 | `Duration.zero` (jumps) |
| Tab label weight/colour | `AnimatedDefaultTextStyle` | 200 ms, `standard`; w600→w700, letter-spacing 0→−0.01×size | 150 ms |
| Bottom bar item / pill item tint | `AnimatedContainer` | 200 ms, `standard`; transparent → accent @ 13 % (bar) / pillActive (pill) | 150 ms |
| Every card / button press (`PressScale`) | raw-pointer listener, unbounded controller | down: `animateTo(0.97, 100 ms, standard)`; release (up, cancel, or move > touch slop 18 px): `SpringSimulation(springMomentum, current, 1, velocity)` | no scaling at all |
| List entrances (`StaggeredEntrance` + `StaggerScope`) | one controller per row, `Interval(delay/total, 1, emphasizedDecelerate)` | rise 16 px (6 px for search rows/history/featured/categories results) + fade; delay = `index (capped at 8) × 40 ms` (60 ms when held by the launch `EntranceGate`), total = delay + 350 ms; only the first batch (rows built in the first frame of a `StaggerScope`) animates; each phase key ('loading', 'status', 'content', search phase keys) re-runs the cascade once | 150 ms fade, no travel, no stagger |
| Scroll to top on second tap | `ScrollController.animateTo(0)` | 300 ms, `standard` (Home store and search tabs) | search: `jumpTo(0)`; Home store: unchanged 300 ms |
| Live feed "Back to the top" (`liveFeedBackToFirst`), Up next selection | `PageController.animateToPage` | 400 ms, `Curves.easeOutCubic` | unchanged |
| Live feed chip / refresh / index follow | `jumpToPage` | instant | — |
| Live preview fade-in | `AnimatedOpacity` on first frame | 250 ms, linear | 150 ms |
| Swipe hint | repeating controller | 2400 ms; `t = easeInOut(1 − |2v − 1|)`; translate y `−6t` | stopped (still) |
| Search tabs row appearing | `AnimatedSize` | 260 ms, `standard`, alignment top | 150 ms |
| Search field focus ring | `AnimatedContainer` | 200 ms, `standard`; border pillBorder 0.5 → accent 1.0 | 150 ms |
| Category tile selection ring | `AnimatedContainer` box shadows | 240 ms, `standard`; spread 0→4 accent and 0→2 ground | 150 ms |
| Browse pane category change | `AnimatedSwitcher` | 280 ms, in/out `standard`; fade + slide from `Offset(12/800, 0)` | 150 ms fade only |
| Offline section chevron | `AnimatedRotation` | 200 ms, linear, 0 → 0.5 turn | not reduced |
| Jump-to-top button (category/tag lists) | `AnimatedSwitcher` | 300 ms, in `easeOut`, out `easeIn` | not reduced |
| Rolling numbers (viewer pills, "Live now N", "N watching") | `RollingNumber` (motion widget) | 450 ms, `standard` | no roll |
| LIVE badge dot (`SignalPing`) | periodic ping | 1200 ms ping, 5 s rest, `standard` | static |
| Skeleton sheen (`SkeletonLoader`) | shared sheen | period 1600 ms, `easeInOut` | no sheen |
| Header glass on pushed pages (search, tag page) | `SettledBlur` | blur applied only once the route transition has settled | same |
| Live preview start delay | `Timer` | 350 ms settle | same |
| Channel open | wait for decoder release | up to 100 ms | same |

Haptics: selection click on a section/tab change (`Haptics.selection`), chip selection in the Live feed, expanding the offline section; light impact on pull-to-refresh (all lists), "Not interested", play by hand, opening a content warning, unmute, enlarging a thumbnail; medium impact before stream/channel actions sheets.

## Network and data

All Helix calls go through `TwitchApi` (`BaseApiClient`, base `https://api.twitch.tv/helix`, app/user token + Client-ID handled by the client, other area). GQL calls POST `https://gql.twitch.tv/gql` with header `Client-ID: kimne78kx3ncx6brgo4mv6wki5h1ko` (Twitch web client id) and a body `{operationName, query, variables}` with **full query text** (no persisted hashes). "Private" GQL adds `Authorization: OAuth <twitch.tv web token>` (`authStore.twitchWebToken`).

## Wide and tablet layout

Breakpoint: `kLargeScreenShortestSide = 600` — `isLargeScreen` when the window's **shortest side ≥ 600 dp** (a split-screen half narrower keeps phone layouts); `LargeScreenScope(large: true)` forces tablet layouts inside a narrower panel (Browse's category pane). Other thresholds: Browse master/detail when tablet and width ≥ `BrowsePage.masterDetailWidth = 1000`; search Top three columns when content width ≥ 1112 (400 + 340 + 2×36 + 300); `StreamCard.rowThumbnailWidth` 200 when the row ≥ 500 wide; Live feed tablet portrait when height > width.

Tablet variants (these become the PC layout):

## PC equivalent

Target: Rust + Slint UI, libmpv for video, Windows first. Use the **tablet layouts as the desktop layout** for any window whose shortest side ≥ 600 logical px; keep the phone layouts for narrow windows (a narrow side-docked window) so behaviour stays identical when resizing. Keep a single widget tree across the breakpoint so pages keep state.

- **Shell**: a top bar (72 px) with brand, pill navigation (Home / Browse / Activity), search field, whispers button, avatar (Profile). Keyboard: `Ctrl+1..4` switch sections, `Ctrl+Tab`/`Ctrl+Shift+Tab` cycle the current section's tabs, `Ctrl+K` or `Ctrl+F` / `/` focus search (opens the search page), `Alt+Left` / `Backspace` (outside text fields) / mouse back button = Android back (`handleBack` semantics, but never quit the app — on the start place do nothing; closing is the window's job). Clicking the active section/tab or pressing `Home` scrolls to top (300 ms, standard cubic). Selection haptics → no-op (optionally a subtle sound off by default).
- **Glass**: emulate blur σ 22/26 + saturate 170 % with Slint's backdrop blur where available; otherwise the opaque tablet bar (no glass) — never blur over video.
- **Mouse/hover**: every `PressScale` card also gets a hover state (raise to the hairline colour or 4 % overlay) and the 0.97 press scale on mouse down with the momentum spring on release; long press = right click (context menu = stream actions / user actions sheet as a popup menu or side sheet); long press on thumbnail (enlarge) = `Shift+click` or a context-menu item "Enlarge preview"; tooltips appear on hover (existing tooltip strings). Touch-down token preload = **mouse down** (and hover-intent after ~150 ms is a recommended extra).
- **Pull to refresh**: a refresh button in the section header plus `F5` / `Ctrl+R`, and over-scroll on touchpads; keep the 5-minute stale auto-refresh on window focus (replaces app resume) and on page becoming visible.
- **Live feed**: vertical paging with mouse wheel (one notch = one page, debounced), `↑/↓` / `PageUp/PageDown` / `J/K`, `Enter` = Watch with chat, `M` = mute toggle, `N` = Not interested, `S` = share (copy `https://www.twitch.tv/<login>` to clipboard with a toast — no share sheet on Windows), `Space` = play preview by hand. Preview via a second, small libmpv instance (muted, `--cache` ~4 MiB, `profile=fast`, `vid` chosen by `pickPreviewVariant` rules, no low-latency tuning), started 350 ms after settling, released before the channel's main player opens (await release ≤ 100 ms). App resume/background → window focus/minimize (`minimized` or fully occluded = background: stop preview). Metered network: Windows `NetworkInformation.GetInternetConnectionProfile().GetConnectionCost()` (`NetworkCostType` ≠ Unrestricted, or roaming/over data limit) replaces Android's metering; subscribe to `NetworkStatusChanged`. Mini player visibility rule unchanged. Up next column clickable; tablet layout on desktop.
- **Clips PiP** (Android picture-in-picture) → a frameless always-on-top mini window (or the global mini player) showing the clip alone; the shell chrome hides in that window state exactly as `chromeHidden`.
- **System bars** (`SystemUiOverlayStyle`) → nothing on Windows except, optionally, the title bar colour matching the ground (`#0A0A0A` dark) via DWM; over video keep dark.
- **Orientation lock release** (`setPreferredOrientations([])`) → no-op.
- **Language prompt / release notes / feedback prompt / update offer / token notice / whisper notices**: same sequencing; sheets become centered modal dialogs (max width 480 for the language prompt) not dismissable by clicking outside; snackbars become bottom toasts above content; feedback "Send" opens the default browser (`launchUrlExternal` irrelevant: always external or in-app webview per setting).
- **Search**: page with the same header; `Esc` clears / then closes (mirrors Clear → Cancel); `Enter` submits; `↓/↑` navigate suggestions & history, `Delete` on a focused history row removes it; keyboard focus starts in the field unless a kept search exists. Persist history in the app's settings store (replacing SharedPreferences `search_history`), same 8-item cap.
- **Scroll**: smooth wheel scrolling; `OnsetScrollbar` → a visible thin overlay scrollbar on hover; jump-to-top button kept.
- **Persistence**: SharedPreferences keys (`last_shown_version`, `search_history`) and settings JSON move to a JSON/TOML file in `%APPDATA%\ONSET\` with identical key names and semantics.
- **Network**: identical Helix and GQL requests (same query texts, operation names, Client-ID, OAuth header), via `reqwest` with cancellation (drop/abort handles replace Dio `CancelToken`), generation counters for stale answers, same backoffs (30 min), TTLs (10 min labels, 5 min staleness, 30 min new-videos recheck), debounces (300 ms search, 150 ms suggestions) and caps.
- **Images**: same thumbnail URL rewriting with the window's scale factor in place of `devicePixelRatio`, same 5-minute cache key; box art 3:4 rewriting; monogram fallback using the exact Dart VM string hash of the category id (see "Monogram hash" under Known Android defects) into the six washes.
- **Accessibility**: map Semantics labels to UI Automation names (Slint `accessible-label`), `selected` states, headers; reduce motion = Windows "Show animations in Windows" off (`SPI_GETCLIENTAREAANIMATION`) → the same 150 ms cross-fades, no travel, no stagger, still swipe hint, no ping/sheen/roll.
- **Haptics**: all `HapticFeedback` calls → no-op.
- **Share** (`shareLink`) → copy link + toast; optional Windows Share UI (`DataTransferManager.ShowShareUIForWindow`).
- **Text scaling**: honour Windows text scale factor exactly like `MediaQuery.textScaler` (shelf height `137 + 9 + scale(40)`, tab widths measured with the scaler, compact search field when the label doesn't fit).
### Known Android defects (fix on PC)

1. **Hero ignores "Hide viewer count".** Android: `LargeStreamCard`'s top-left pill (`OverlayPill` + `RollingViewers`) shows the viewer count even when `hideViewerCount` is on (every other count is hidden). PC: hide that pill (and its semantics label) when the setting is on, like `ViewerPill`.
2. **Categories store lifetime.** Android: `BrowsePage`'s `CategoriesStore` is `late final` — the top-categories request is only sent when the Categories tab is first built, and the store is never disposed (no dispose, its future can complete after the page is gone). PC: create it with the Browse page (or prefetch at idle) and drop/cancel it when the page is destroyed.
3. **Live feed staleness uses the wall clock.** Android: `LiveFeedStore.stale` and `refresh()` use `DateTime.now()`, so a wall-clock change (DST/manual clock) can force or suppress the 5-minute refresh. PC: use a monotonic clock (`Instant`) for staleness and TTLs.
4. **topTags can show 9 chips.** Android: when the selected tag is outside the 8 most used, the chip row shows selected + 8 = 9 tags (selected inside the top 8 → selected + 7 = 8). **PC decision: at most 8 tag chips in total — the selected tag (if any) first, then up to 7 others in rank order, never repeating the selected one** (no selection → the 8 most used). The ported test "tags rank by use, filter the list, and stay listed when picked" is adapted to this cap.
5. **Stale ListStore pages leave nothing to clean.** Not a visible bug today (the newer request owns the loading flag), but a stale answer that arrives after the newer one has finished never re-runs hype trains / sort paging; PC must keep the same rule: only the current generation touches loading state and follow-ups.
6. **Related lives strip misaligned and cards touching.** Android: the strip's padding is `gutter + window.left − 8` / `gutter + window.right − 8`, but tile-mode `StreamCard`s have zero horizontal padding, so nothing absorbs the −8: the first card starts 8 dp left of the "Related lives" title (x = 8 on a phone, 20 on a tablet, vs title at 16 / 28) and card edges touch. PC: remove the −8 (pad `gutter + inset` both sides) and put a 12 px gap between cards.
7. **Stale search results during the debounce.** Android: for 300 ms after each keystroke the previous query's channels/categories stay shown (skeletons only for the first query), while "Go to channel “<new text>”" and the featured card are computed from the new text against the old list. PC: on every non-empty text change clear the channel/category results (and related lives) immediately and show skeletons until the debounced search runs.
8. **Spaces-only / untrimmed queries.** Android: `onSearchTextChanged` and `handleQuery` test `query.isEmpty`, so "   " calls `/search/channels` and `/search/categories` with `query=%20%20%20` and is saved to history; "Go to channel" passes the raw text to `getUser(userLogin:)`, so " xqc" is "not found". PC: trim the query before deciding emptiness, before searching, before saving to history and before "Go to channel" (the videos store, suggestions and `featuredChannel` already trim).
9. **Related lives ignore blocked and hidden channels.** Android: `_loadRelatedLives` only removes channels already shown live; blocked users and `hiddenChannelIds` can appear (every other list removes blocked users; Browse lists remove hidden channels). PC: also remove `authStore.user.blockedUsers` ids and `settings.hiddenChannelIds` before taking 6.
10. **Followed-videos badge leaks across accounts.** Android: `NewFollowedVideos.count` and `_checkedAt` are process-wide statics never reset on account change, and `followedVideosSeenAt` is one global setting: switching account A → B within 30 min shows A's count on B's tile, and later B's videos are counted against A's seen time. PC: key the seen time, the count and the recheck clock by user id, and reset the in-memory state on account change.

**Monogram hash (not a defect — reproduce exactly).** `_Monogram` picks `_washes[seed.hashCode.abs() % 6]` with `seed = category.id`. The Dart VM (`runtime/vm/hash.h` + `StringHasher` in `runtime/vm/object.h`, SDK 3.10) hashes a string's **UTF-16 code units** with 32-bit unsigned wrapping arithmetic:
```
h: u32 = 0
for each UTF-16 code unit c:      // CombineHashes
    h = h + c
    h = h + (h << 10)
    h = h ^ (h >> 6)              // logical shift
// FinalizeHash(h, kHashBits = 30)
h = h + (h << 3)
h = h ^ (h >> 11)
h = h + (h << 15)
h = h & ((1 << 30) - 1)
if h == 0 { h = 1 }
```
The result is always in `1 ..= 2^30 − 1`, so `.abs()` is the identity; index = `h % 6`. Category ids are ASCII digits (one-byte strings in the VM; same code units). Vectors verified on the Dart 3.10.3 VM (`dart run`, 2026-11-18): `"509658"` → 940227327 → wash 3; `"21779"` → 935305111 → wash 1.

(Live feed calls it with 720 on tablet, 480 on phone.)

**`LivePreviewController extends ChangeNotifier`** — plays one live channel's preview at a time, muted. Params: `resolveUrl`, `createBackend` (default `MediaKitPreviewBackend.new`), `settle = 350 ms`, `startMuted` (bool Function()?, default true). Rules: one decoder ever (a new preview starts only once the previous is disposed); a preview starts after `settle` so a fast swipe never starts a decoder per channel; `setActive(false)` stops it at once; every preview starts muted (or per `startMuted` = setting "mute previews"); `toggleMute` changes only the current one.
State: `_target`, `_active`, `_timer`, `_resolving` (CancelToken), `_generation`, `_backend`, `_playing`, `_released` (Future chain of decoders being let go), `_disposed`, `_muted = true`, `_failed`. Getters: `backend`, `playingLogin`, `targetLogin`, `idle` (= `_released`), `muted`, `failed`.
`show(login)`: no-op if same target; else set target, `_restart()`. `setActive(active)`: no-op if same; set; `_restart()`. `toggleMute()`: no backend → return; flip `_muted`, notify, `await backend.setVolume(muted ? 0 : 1)` (catch → `debugPrint('Preview volume failed: ${e.runtimeType}')`). `stop()`: `_active = false; _restart()`.

`_release()`: take backend, null `_backend` and `_playing`; chain `_released = previous.then(backend.dispose)` (catch → `debugPrint('Preview release failed: ${e.runtimeType}')`).
`_start(login, generation)`: `await _released`; drop if generation changed or disposed; `_resolving = CancelToken()`; `url = await resolveUrl(login, cancel)` — on error: if cancelled return silently; else `debugPrint('Preview unavailable: ${e.runtimeType}')` and if still current → `_failed = true`, notify; return. `refreshStreams()` (action): `_error = null`; followed → `await getPinnedStreams()`, `unawaited` categories and streaks (a slow gql.twitch.tv must never hold the live list back), if offline expanded → reset cursor, `await getOfflineChannels()`. `_streamsGeneration++`, cursor null, `await getStreams()`.

`_getCategoryDetails()`: `twitchApi.getCategory(gameId)` (`GET /games?id=`) → `_categoryDetails = data.firstOrNull`; error → `debugPrint('Category details error: $e')` (header stays placeholder); finally loading false (never left loading: would stop paging).

`_onScroll()`: `showJumpButton = !(position.atEdge || position.outOfRange)`.
`dispose()`: all six reaction disposers; remove scroll listener (controller left alone).
